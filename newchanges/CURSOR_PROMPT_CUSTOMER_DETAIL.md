# پرامپت توسعهٔ صفحهٔ جزئیات مشتری - برای Cursor

## خلاصهٔ پروژه
ساخت صفحهٔ **Customer Detail** برای سیستم CRM/سیستم پیش‌بینی موفقیت مذاکره. وقتی کاربر روی یک مشتری کلیک کنه، این صفحه بازشه و اطلاعات تفصیلی + امتیاز موفقیت مذاکره رو نمایش بده.

**Backend API در دسترس**: `http://localhost:8000/score/{customer_id}`

---

## ۱. ساختار و Layout

### Layout کلی
- **Sidebar چپ**: نیاز نیست، حذف شود تا فضای بیشتری برای محتوا باشه
- **Breacrumb**: `مشتریان > [نام مشتری]` (بالا راست)
- **Header بزرگ**: نام مشتری و شناسه‌ی او با آیکون کپی
- **سه ستون اصلی**:
  1. **ستون چپ (۲۰٪)**: بخش‌های فیلتر/عمل (پیشنهادات، فرصت‌ها، اقدام)
  2. **ستون میانی (۶۰٪)**: محتوای اصلی (سلامت رابطه، پیشنهاد AI، بینش‌های کلیدی)
  3. **ستون راست (۲۰٪)**: فراخوانی سریع (شماره، ایمیل، ...)

## ۸. API Integration

### درخواست
```javascript
// هنگام بارگذاری صفحه
fetch(`http://localhost:8000/score/{customer_id}`)
  .then(res => res.json())
  .then(data => {
    // استفاده از data.negotiation_score
    // استفاده از data.pillars (collection, retention, loyalty, cash)
    // استفاده از data.key_drivers
    // استفاده از data.recommendation
  })
```

### داده‌های مورد نیاز
- `customer_id` (از URL parameter)
- `negotiation_score` (امتیاز نهایی ۰-۱۰۰)
- `pillars`: object با چهار محور (هر کدوم دارای score, note, confidence)
- `recommendation`: متن توصیه
- `key_drivers`: لیست‌سازیهای کلیدی
- `customer_info`: segment, status, sales_rep_id, location

## ۱۰. Interaction Patterns

1. **Hover روی recommendation**: dropdown فرمول بازشود
2. **کلیک دکمهٔ "شروع تماس"**: modal یا جدید tab برای logging call
3. **کلیک "ایجاد وظیفه"**: sidebar یا modal برای وظیفهٔ جدید
4. **Key drivers**: tooltip برای توضیح دقیق‌تر

## ۱۱. ملاحظات نهایی

✅ **RTL (Right-to-Left)** — صفحه تماماً فارسی
✅ **نمایش درصد‌ها** — بدون علامت ٪ (مثل: ۲۸ از ۱۰۰، یا صرفاً ۲۸)
✅ **تاریخ‌ها** — به روزها نسبت بده (مثل: ۷۰ روز پیش)
✅ **Error handling** — اگر API fail شود، پیام مناسب نمایش بده
